# Digital Professor Bot

**Digital Professor** — это бот MAX, разработанный для повышения вовлеченности студентов в онлайн-курсы и мотивации к регулярному обучению. Бот использует интерактивные напоминания (пинги), адаптивную коммуникацию на основе личностных особенностей студента (модель Big Five), интеграцию с Moodle и систему RAG (Retrieval-Augmented Generation) для ответов на вопросы по курсам.

## 🌟 Основные особенности

*   **RAG-система для вопросов по курсам:** Бот отвечает на вопросы студентов по материалам курсов, используя технологию RAG с поддержкой нескольких доменов (математика, вайбкодинг).
*   **Интеграция с Moodle:** Автоматическое получение курсов, отслеживание прогресса, показ дедлайнов и следующего задания.
*   **Интерактивные напоминания (Пинги):** Бот отправляет регулярные напоминания студентам о необходимости приступить к обучению.
*   **Персонализированные пинги:** Текст напоминаний динамически адаптируется под личностный профиль студента (Big Five), делая общение более мотивирующим и поддерживающим.
*   **Оценка личностных черт (Big Five):** Бот определяет уровень пяти ключевых личностных черт: Экстраверсия, Дружелюбие, Добросовестность, Эмоциональная стабильность, Открытость опыту.
*   **Автоматическое обновление профиля Big Five:** Профиль студента автоматически пересчитывается еженедельно на основе его активности и взаимодействия с ботом.
*   **Система обратной связи:** Пользователи могут оценивать качество ответов RAG для улучшения системы.
*   **Защита от злоупотреблений:** Многоуровневая система защиты с rate limiting и LLM-цензором для проверки запросов.

## 🧠 Как это работает

### 1. Регистрация и настройка профиля

*   При первом взаимодействии бот запрашивает:
    *   ФИО студента
    *   Номер студенческого билета (для интеграции с Moodle)
    *   Часовой пояс (Екатеринбург/Москва)
    *   Время получения напоминаний
*   После регистрации бот автоматически получает список курсов студента из Moodle.
*   При первом запуске может быть предложен короткий опрос для формирования начального профиля Big Five.

### 2. Работа с курсами

*   **Просмотр курсов:** Студенты видят список своих курсов из Moodle (например, "Математика", "Вайбкодинг").
*   **Отслеживание прогресса:** Для каждого курса отображается процент выполнения и следующее задание.
*   **Дедлайны:** Бот показывает ближайшие дедлайны из Moodle.
*   **Задавание вопросов:** Для каждого курса доступна функция "Задать вопрос по курсу", которая использует RAG-систему для ответа на вопросы по материалам курса.

### 3. RAG-система для вопросов по курсам

*   **Выбор домена:** При выборе курса автоматически определяется домен (математика или вайбкодинг).
*   **Поиск релевантной информации:** Система ищет релевантные фрагменты из базы знаний курса.
*   **Генерация ответа:** LLM генерирует подсказку с направляющим вопросом (не полное решение).
*   **Продолжение диалога:** Поддержка многошагового диалога с контекстом предыдущих сообщений.
*   **Система обратной связи:** После каждого ответа пользователь может оценить его полезность.
*   **Защита:** Многоуровневая защита от злоупотреблений (rate limiting, валидация входных данных, LLM-цензор).

### 4. Регулярные пинги

*   Студенты настраивают расписание получения напоминаний:
    *   По дням недели (например, понедельник, среда, пятница)
    *   По частоте (1-7 раз в неделю)
*   В назначенное время бот отправляет персонализированный пинг с вопросом о готовности приступить к обучению.
*   **Динамический текст пинга:** Бот генерирует персонализированное сообщение с помощью Open Router LLM, опираясь на текущий профиль Big Five студента.

### 5. Еженедельный опрос

*   **Автоматическая отправка:** Каждую пятницу после основного пинга бот автоматически отправляет еженедельный опрос пользователям (если опрос еще не был отправлен на этой неделе).
*   **Вопросы опроса:**
    1. Понятен ли тебе материал, который вы изучили на этой неделе? (Да/Нет)
    2. Есть ли пробелы в знаниях по прошлым темам? (Да/Нет)
*   **Дополнительный вопрос:** Если пользователь отвечает "Да" на второй вопрос, бот просит указать название темы, по которой возникли сложности.
*   **Сохранение данных:** Все ответы сохраняются в базе данных для анализа и помощи преподавателям в выявлении проблемных тем.
*   **Защита от дублирования:** Система проверяет, был ли уже отправлен опрос на текущей неделе, чтобы не беспокоить пользователей повторно.

### 6. Еженедельное обновление Big Five

*   Каждую неделю (по расписанию, обычно в понедельник в 03:00 UTC) бот собирает данные об активности студента:
    *   Ответы на пинги и их связь с выполнением заданий.
    *   Фактически выполненные задания из moodle.
    *   Изменение прогресса по курсам из moodle
    *   Активность взаимодействия пользователя с RAG
*   Эти данные анализируются (с помощью Open Router LLM) и используются для корректировки профиля Big Five.
*   Профиль сглаживается по сравнению с предыдущей неделей (используется EMA - экспоненциальное скользящее среднее) для плавных изменений.
*   Обновленный профиль влияет на стиль общения бота в будущих пингах.

### 6. Настройки профиля

Пользователи могут изменять:
*   Часовой пояс
*   Время получения напоминаний
*   Номер студенческого билета (при изменении автоматически обновляется список курсов из Moodle)

## 🛠 Техническая архитектура

### Языки и фреймворки

*   **Python 3**
*   **MAX Bot API** (`platform-api2.max.ru`) — доставка сообщений и кнопок
*   **`langchain`** - для интеграции с LLM и работы с RAG
*   **`chromadb`** - векторная база данных для хранения эмбеддингов документов
*   **`open-router`** - API для работы с LLM
*   **`APScheduler`** - для планирования отправки регулярных пингов и еженедельных задач
*   **`SQLite`** - легковесная встраиваемая СУБД для хранения данных
*   **`httpx`** - для асинхронных HTTP-запросов к Moodle API

### Взаимодействие с LLM

*   Используется модели Mistral-small-3.1-24b и Qwen3-235b через `open-router`.
*   Реализован кастомный класс `YandexChatModel`, наследуемый от `BaseChatModel` Langchain. 
*   Поддерживается как синхронный, так и асинхронный вызов модели.
*   Используется для:
    *   Генерации персонализированных текстов пингов
    *   Оценки открытых и практических заданий
    *   Анализа активности для обновления профиля Big Five
    *   Генерации ответов в RAG-системе

### RAG-система

*   **Векторная база данных:** Используется ChromaDB для хранения эмбеддингов документов курсов.
*   **Домены:** Поддержка нескольких доменов (math, vibe/vibecoding) с отдельными экземплярами RAG pipeline.
*   **Embeddings:** Используются провайдеры эмбеддингов от OpenAI для преобразования документов в векторы.
*   **Retrieval:** Поиск релевантных фрагментов по запросу пользователя, через косинусную близость.
*   **Generation:** Генерация ответа с использованием найденного контекста и истории диалога.
*   **Защита:** Многоуровневая система защиты:
    *   Rate limiting (ограничение частоты запросов)
    *   Валидация входных данных
    *   LLM-цензор для проверки релевантности и безопасности запросов

### Интеграция с Moodle

*   Используется Moodle REST API для получения данных о курсах и прогрессе студентов.
*   Автоматическое обновление списка курсов при изменении студенческого билета.
*   Получение информации о:
    *   Курсах студента
    *   Прогрессе выполнения курса
    *   Дедлайнах заданий и тестов
    *   Следующем невыполненном задании

### База данных (SQLite)

Бот использует SQLite для хранения всей информации. Основные таблицы:

*   **`users`**: Основная информация о пользователях (ID, имя, студенческий билет, часовой пояс, время пинга, флаг администратора, флаг инициализации Big5, список курсов Moodle).
*   **`responses`**: История ответов пользователей на пинги (`id`, `user_id`, `status`, `timestamp`, `task_id`, `meta_data`).
*   **`courses`, `topics`, `tasks`**: Структура курсов, тем и заданий.
*   **`course_assignments`**: Назначение курсов пользователям.
*   **`weekly_progress`**: Недельный прогресс пользователя по курсам (`user_id`, `course_id`, `week_start`, `fact`, `kpi`).
*   **`test_questions`, `test_choices`, `task_results`**: Детали тестов, варианты ответов и результаты выполнения всех типов заданий.
*   **`big5_profiles`**: Текущий профиль Big Five для каждого пользователя (`user_id`, `extraversion`, `agreeableness`, `conscientiousness`, `emotional_stability`, `openness`, `last_updated`, `meta_data`).
*   **`big5_history`**: История изменений профиля Big Five по неделям (`id`, `user_id`, `week_start`, шкалы Big5, `meta_data`).
*   **`ping_logs`**: Журнал отправленных пингов (`id`, `user_id`, `ping_type`, `sent_at`, `message_text`, `big5_profile_id`, `meta_data`).
*   **`rag_interactions`**: Логи взаимодействий с RAG-системой (`id`, `user_id`, `user_query`, `retrieved_context`, `llm_response`, `feedback`, `created_at`).
*   **`ping_schedules`**: Расписание пингов пользователей (`user_id`, `pings_per_week`, `ping_days`, `last_ping_date`).
*   **`weekly_pings`**: Ответы пользователей на еженедельные опросы (`id`, `user_id`, `student_id`, `username`, `answer1`, `answer2`, `topic_name`, `timestamp`).

### Планировщик задач

*   Используется `APScheduler` для управления расписанием.
*   **Еженедельный пересчет Big Five:** Задача запускается каждый понедельник в 03:00 UTC (`_weekly_big5_job`).
*   **Персональные пинги:** Для каждого пользователя создается индивидуальная задача `CronTrigger` для отправки пингов в установленное время и дни недели (`send_reminder`).
*   **Еженедельный опрос:** Автоматически отправляется в пятницу после основного пинга (если еще не был отправлен на этой неделе).
*   **Перепланирование:** При изменении расписания пингов задачи автоматически перепланируются.

## 📋 Команды бота

### Команды для пользователей

*   `/start` - Начало работы с ботом, регистрация или возврат в главное меню
*   `/help` - Справка по использованию бота
*   `/menu` - Открыть главное меню

### Команды для администраторов

*   `/create_course <key>` - Создание курса по ключу из реестра курсов
*   `/assign_course <course_id> <user_id> <n_times>` - Назначение курса пользователю с указанием целевого количества заданий в неделю
*   `/setpings <user_id> <параметры>` - Настройка расписания пингов для пользователя
    *   Параметры: дни недели (monday, wednesday, friday) или частота (1-7)
*   `/setpingsall <параметры>` - Настройка расписания пингов для всех пользователей
*   `/testping <user_id>` - Тестовая отправка пинга пользователю
*   `/forceping <user_id>` - Принудительная отправка пинга (игнорирует ограничения расписания)
*   `/testweeklysurvey <user_id>` - Тестовая отправка еженедельного опроса
*   `/recalc_big5` - Ручной пересчет профиля Big Five (для тестирования)

## 🔧 Установка и запуск

### Требования

*   Python 3.8+
*   SQLite
*   Доступ к Open Router моделям
*   Доступ к Moodle API (для интеграции с Moodle)

### Переменные окружения

Создайте файл `.env` со следующими переменными:

```
MAX_BOT_TOKEN
MOODLE_URL
MOODLE_TOKEN
COURSE_ID_1=8788
API_KEY
```

### Установка зависимостей

```bash
pip install -r requirements.txt
```

### Запуск

```bash
python main.py
```

## 🔒 Безопасность

*   **Rate Limiting:** Ограничение частоты запросов для предотвращения злоупотреблений
*   **Валидация входных данных:** Проверка корректности данных перед обработкой
*   **LLM-цензор:** Проверка релевантности и безопасности запросов с помощью LLM
*   **Санитизация:** Очистка пользовательского ввода от потенциально опасных символов
*   **Приватные чаты:** Бот работает только в приватных чатах с пользователями

## 📝 Логирование

Все важные события логируются:
*   Регистрация пользователей
*   Отправка пингов
*   Взаимодействия с RAG
*   Ошибки и предупреждения
*   Административные действия

Уровень логирования настраивается через переменную окружения `LOG_LEVEL`.
